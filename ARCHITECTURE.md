# Architecture

The exercise Hear note source is shared by `Practice.tsx` and `FingerboardTrainer.tsx` through `exercise-sound.ts` and `ExerciseSoundSelector.tsx`. Its local-storage key is separate from the tuner's. A lookup requires both pitch and suggested string; the open-A and D-string fourth-finger A4 recordings remain distinct. `ExerciseReferencePlayback` wraps the existing output-only Tone and violin sample players, cancels pending loads on target changes, and falls back to Tone on absent or failed clips. Each screen suppresses its `PracticeSession` indefinitely during loading/playback, then replaces that with the existing settling window. The scoring engines, Hear pattern, detector, and tuner are unchanged. The nine added short samples and their measured fundamentals are documented in `VIOLIN_SAMPLES.md`; the existing PWA WAV precache includes them for first playback offline.

The score and standalone trainer share `PracticeControls.tsx` for listening and restarts. In Guided lessons, `Staff.tsx` shares beat-based notehead coordinates with a separate SVG hold overlay. The overlay tracks `SustainEngine` output without controlling scoring. Its progress can reset without moving the track, which follows the current note index alone. The pitch trace breaks on unmeasured frames and resets on interruption. The three fingerboard tunes use the exercise’s written string/finger suggestions to select positions, including where two different positions share a pitch.

Milestone 2E adds `src/fingerboard.ts` as reusable written-pitch and suggested-position data. Each position has a unique string/row ID even if it shares frequency with another position. It builds seeded Find the Note sequences and short walks. `FingerboardTrainer.tsx` owns a single `AudioSession`, a Quick Check `PracticeSession`, and shared reference playback; `FingerboardChart.tsx` draws the nut and four strings. Stopped notes use the equal-tempered distance from the nut, 1 − 2^(−semitones/12), scaled to the fourth-finger span for display. Open notes sit above the nut because they require no finger placement. Staff mode reuses `Staff.tsx`. Capture, detector thresholds, existing lessons, and tuner are unchanged. Only the active screen owns a microphone session; leaving the trainer stops it and disposes playback. The trainer marks unsupported chart pitches using the unchanged exercise detector bounds at the current A4 reference.

The React shell in `src/App.tsx` owns the three screens and the microphone session. `src/Staff.tsx` renders exercise note data as SVG using VexFlow; it uses an actual treble clef and VexFlow's ledger lines. Each note is a whole note in its own strict 4/4 measure, with a time signature, metronome mark, and final barline.

`src/audio.ts` owns `getUserMedia`, Web Audio nodes, polling, and cleanup. It never connects the microphone to speakers. `src/pitch.ts` wraps Pitchy's McLeod pitch estimate, rejects low RMS/clarity/out of range readings, and median smooths accepted frequencies. `src/music.ts` converts frequencies to named octaves and signed cents from the actual target. `src/exercise.ts` tracks sustained matches, ordered progression, and release between targets. `src/config.ts` centralizes thresholds. `src/tempo.ts` holds pure timing functions (whole note = 240 / BPM s). `src/sustain.ts` is the two-phase sustained-note engine (find, then hold for the written duration) and shares the `PracticeEvaluation` result shape. `src/practice-session.ts` builds the exercise notes for the selected string focus, routes readings to the sustained engine or the unchanged quick `ExerciseEngine`, and enforces reference-tone suppression. `src/tone.ts` is an output-only Web Audio reference tone player with its own lazily created AudioContext; it never connects to the microphone graph. `src/Practice.tsx` owns the practice screen and its microphone session (as `Tuner.tsx` does for the tuner) and throttles React updates to about 10 per second. This separation allows swapping pitch detection, capture, notation, or exercises independently.

Pitchy's `forFloat32Array(4096)` and `findPitch(samples, sampleRate)` API was verified against its published documentation. The application pins dependencies and a lockfile. The detector's clarity is a signal quality heuristic, not a calibrated probability. Audio and UI are entirely client side.

The analysis window is 4096 samples (about 85–93 ms at common sample rates), polled every 50 ms. Analyser frames overlap. One isolated pitch jump is quarantined; two consistent observations establish a transition. Rejected frames produce no accepted pitch, and smoothing history expires after more than two consecutive rejected frames. The engine permits up to 110 ms between verified matching observations, but silence or a verified wrong pitch resets a hold. Advancing requires a fresh correct observation after 350 ms. A 180 ms continuous quiet period, or a confirmed pitch change, releases the next target. These settings are starting points for physical testing, not universal violin thresholds.

Sustained-note timing uses the same `performance.now()` timestamps as the audio poll, so engine tests drive it with a controllable clock. The hold measures the gap since the last verified good reading before accepting a new one, so a microphone interruption (no readings at all, such as a suspended AudioContext) longer than the grace period resets the hold even if the next frame is correct. Reference suppression discards all evidence for the current note and any release-in-progress, so the app's own tone cannot start, extend, or complete a note.

Milestone 2B adds a data layer for the curriculum. `src/notation.ts` holds written-pitch spelling (step, accidental, octave), MIDI and frequency derivation from the A4 reference, key signatures, and the conventional accidental rule (key signature applies in every octave; an accidental lasts to the barline for that step and octave; naturals cancel). `src/curriculum.ts` defines exercises as data using compact tokens such as `F#4:h@D2^` (F♯4, half note, D string, high 2nd finger), validates them (4/4 beat totals, detector range across the A4 range, first-position fingering consistency), and flattens them into `PracticeNote`s that carry measure, duration, beats, printed accidental, and fingering. Written spelling is kept separate from detection: matching is by frequency, so enharmonic spellings match the same sound, and the app never infers string or finger. `SustainEngine` now takes each note's `beats`; the engines are otherwise unchanged. `src/layout.ts` places noteheads on a fixed beat grid including the last measure. `Staff.tsx` engraves strict 4/4 VexFlow measures with printed accidentals and a final barline in one continuous strip. A separate fixed clef, key, time signature, and tempo lead the strip. Noteheads, names, fingering, and the hold overlay translate together as the active note changes. Practice preferences store mode, note-name hint mode, and per-exercise tempo and fingering choices; Milestone 2A settings are migrated.

Milestone 2C redesigns only the tuner's presentation. Capture, Pitchy analysis, `TUNER_PITCH_SETTINGS`, `TunerPresentation` smoothing, `classifyString`, and the ±10-cent band are unchanged. `src/trail.ts` is a pure, timestamp-driven trail: each valid reading becomes a point (cents relative to the active target), segments break on silence, uncertain input, non-target notes, or more than 200 ms without readings, the trail clears whenever the target changes, and a point older than 250 ms is never shown as live. `tunerReadout` in `src/tuner-logic.ts` turns a display frequency into the target, highlighted peg, heard note, valid cents, and direction or mismatch text for Manual, Auto, and Chromatic. `Tuner.tsx` draws the trail on a canvas in a `requestAnimationFrame` loop using elapsed time, so it scrolls steadily however readings arrive (about 4 updates per second under `prefers-reduced-motion`); React state updates are throttled to about 10 per second. `ViolinScroll.tsx` is an original inline SVG scroll and pegbox (D and G pegs left, A and E right, as on a violin seen from the front) with real buttons for each string.

Milestone 2D adds only optional pattern metadata to curriculum exercises. Flat note indices let a group cross measures. `src/pattern.ts` selects the current group and keeps both tune-challenge answers hidden until reveal. `PatternGuide.tsx` shows a small original relative-spacing strip and text cue without changing the score; the VexFlow staff and exercise engines remain shared. For the four-bar 05H challenge only, `Staff.tsx` permits read-only page inspection before listening, then follows the current note during practice. `pattern-demo.ts` sequences the existing synthesized tone player. `PracticeSession.suppress` covers the whole demonstration, its gaps, and settling, and any active demo is cancelled on restart or exit. The original note-name and fingering preferences remain independent of the new per-exercise pattern-cue preference.

The tuner's optional Violin sound uses four local, measured open-string WAVs (`src/violin-samples.ts`, `public/samples`). `ViolinSamplePlayer` creates and resumes an output-only AudioContext from the Hear note gesture, aborts loading on cancellation, and sets Web Audio playback rate to target frequency divided by the clip's measured fundamental. The existing `ReferenceTonePlayer` remains the default and is the fallback if a sample cannot load or decode; Chromatic always uses Tone. `Tuner.tsx` suppresses microphone readings during loading, playback, and settling, and cancels both players on target change or exit. The PWA precaches the WAVs. Source and preparation details are in `VIOLIN_SAMPLES.md`.
