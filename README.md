# Violin Studio

A local, microphone based violin practice companion. Open Strings Practice checks sustained pitch while reading a treble clef staff. The independent Instrument Tuner provides continuous violin-string or chromatic feedback without scoring.

## Requirements and setup

- Windows with current Chrome or Edge, a microphone, and Node.js 22.12+ (Node 26 tested).
- From `A:\ViolinStudio`, run `npm ci`, then `npm run dev`.
- Open the localhost URL printed by Vite. Choose **Open Strings Practice**, then **Start Listening**. Microphone permission is requested at that point.
- Choose **Instrument Tuner** directly from Home to tune without an exercise. Select a violin string or Chromatic mode, set the A4 reference (415–466 Hz; default 440 Hz), then start listening. The tuner shows the detected note and octave, signed cents, a smaller Hz readout, and **In tune / Tune up / Tune down** in text. A live pitch trail plots cents against the active target (flat left, sharp right, in-tune line in the centre); the newest valid reading is at the top and about three seconds of history drift downward and fade, with gaps for silence or uncertain input. Pick a string with the G, D, A, and E buttons beside the pegs of the violin scroll. In Manual (default) the selected string stays highlighted; a different note is shown as, for example, “Target D · Hearing A4” and is not plotted. **Auto** highlights the open string the tuner identifies (nearest within 300 cents); tapping a peg returns to Manual. Chromatic mode uses the nearest equal-tempered note and selects no peg. The in-tune zone is ±10 cents. A4 is stored locally and also sets the practice exercise's target frequencies.
- Use **Stop Listening** or **Exercises** to release the microphone. For a local production build, use `npm run build` followed by `npm run preview`.

The application has no account, backend, telemetry, or runtime web service. The production build is an installable PWA. Open it once online and wait for **Available offline** before disconnecting; **Preparing offline access…** means the initial cache is still being created. On Android Chrome, open the HTTPS site and use **Install app** from the browser menu. Browser microphone access requires a secure context, which includes HTTPS and `localhost`. Installation and real Android microphone behavior have not yet been physically verified.

## Checks

`npm test` runs musical logic, tuner calculations, synthetic signal, progression, and audio cleanup tests. `npm run build` type checks and builds the production assets. `npm run test:e2e` runs development Edge browser checks using injected synthetic microphone streams. Set `PW_CHANNEL=chrome` to run the browser suites with an installed Google Chrome instead (for example on Linux). After a build, `npm run test:pwa` checks the manifest, icons, precache, offline launch, navigation, update waiting, and narrow viewport in Edge. Edge must be installed locally for browser tests.

The signal fixtures include sine and harmonic rich tones at 44.1 and 48 kHz, near target intonation, silence, noise, and a strong second harmonic. These characterize the Pitchy based pipeline but cannot establish performance on an acoustic violin. Follow [MANUAL_TEST_PLAN.md](MANUAL_TEST_PLAN.md) before treating live note recognition as validated.

## Current behavior and limits

The home screen lists a data-driven exercise library (`src/curriculum.ts`): 01 Open Strings, 02 String Crossings, 03 First Finger, 04 D-String Walk, 05 A-String Walk, 06 D Major Scale, 07 G Major Scale, and three short original melodies (08A–C). Each exercise defines its key signature, 4/4 time, recommended tempo, measures of whole and half notes with written spelling (including sharps), and optional suggested string and finger. Frequencies are derived from spelling and the A4 reference, never stored. All written notes stay within the detector's 160–800 Hz range at any supported A4.

In the default **Guided: find & hold** mode each note has two phases: first find the pitch (unlimited time, ±25 cents, 350 ms stable), then hold it for its written length at the selected tempo (40–120 BPM; a whole note is 4 beats, a half note 2; the count starts once the pitch is steady, so there is no rhythm scoring). During the hold, drift within ±35 cents and interruptions up to 450 ms are tolerated; a longer interruption, or fault time above 25% of the note (but never less than one 450 ms grace period, so short notes still allow one brief bow change), returns only the current note to the find phase. Completion needs a fresh in-tune reading, so silence or a stale estimate cannot finish a note. **Quick check** mode keeps the original 350 ms recognition. **Hear note** plays a short synthesized reference tone; the microphone result is ignored while it plays and for 400 ms afterwards.

Students can pick any exercise, restart the note or exercise, repeat or move to the next exercise from the completion summary, change tempo (remembered per exercise), show note names always, only after each note is played, or never, and show or hide suggested string and finger (on by default for exercises 01–05). Exercise 01 keeps single-string focus practice. On narrow screens the staff shows a page of whole measures that turns as the student progresses. The completion summary reports notes practised, tempo, and how many notes needed another try; it does not judge bowing, posture, finger placement, or tone. All thresholds are in `src/config.ts`. The next note requires a brief release or a distinct pitch change, so one continuous sound cannot pass repeated notes. Exercises are deterministic and can be repeated freely.

Pitch accuracy depends on microphone placement, room noise, and bowing. A single frequency estimate cannot diagnose fingering, posture, bow grip, or cause of an intonation error. The UI shows uncertainty and waits instead of advancing. Note names can be hidden, but the staff remains visible.

The tuner uses the same detector with a continuous tracking profile and a separate responsive display smoother. Its supported range is 130–1200 Hz; the exercise keeps its 160–800 Hz conservative profile. A reliable estimate outside the tuner range is labeled unsupported. Bowed notes provide more analysis frames; short pizzicato notes may decay before a reliable estimate appears. Harmonics can cause octave mistakes despite outlier rejection. Violin-mode guidance treats a pitch within about 300 cents of the selected string as a potentially detuned string; it cannot identify the physical string. This is equal-tempered tuning relative to the selected A4; pure fifths can differ slightly. Compare the tuner with a conventional chromatic tuner on a real violin using [MANUAL_TEST_PLAN.md](MANUAL_TEST_PLAN.md) before relying on it for setup.
